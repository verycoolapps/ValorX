# JOBS TO BE DONE — REFERENCE

> Clayton Christensen & Tony Ulwick — The theory that consumers "hire" products
> to accomplish specific jobs. Understanding the job unlocks true market insight.

---

## THE CORE INSIGHT

> *"People don't want a quarter-inch drill. They want a quarter-inch hole."*

Consumers don't buy products.
They **hire** products to accomplish something in their lives.

The product is a means. The **job** is the end.

This reframe transforms how you:
- Define your market (everyone trying to do the same job)
- Identify competitors (everything hired to do that job, including "do nothing")
- Prioritize features (those that best complete the job)
- Measure success (did the job get done? how well? how often?)

---

## JOB DIMENSIONS

### Functional Dimension
The practical task the consumer is trying to accomplish.

```
Structure: [Verb] + [Object] + [Context]

Examples:
- "Manage cash flow across my business locations"
- "Prepare healthy meals for my family on weekdays"
- "Learn a new skill within my commute time"
- "Find reliable childcare while I'm at work"
```

**Job statement quality criteria:**
- Starts with a verb (action-oriented)
- Specifies the object (what is being done to what)
- Includes context when critical (when, where, with whom)
- Remains technology-agnostic (doesn't name the solution)
- Stable over time (jobs don't change; solutions do)

---

### Emotional Dimension
How consumers want to feel while doing the job and after accomplishing it.

```
Examples:
- "Feel confident that my financial data is accurate"
- "Feel proud of the progress I'm making"
- "Feel in control, not overwhelmed"
- "Feel connected to something larger than myself"
```

---

### Social Dimension
How consumers want to be perceived by others when doing the job.

```
Examples:
- "Be seen as a responsible business owner"
- "Be recognized as an innovative thinker"
- "Be known for making healthy choices"
- "Be perceived as someone who has their life together"
```

## DESIRED OUTCOMES

Consumers don't just want to do the job — they want to do it **well**.
Desired outcomes are the metrics consumers use to measure success.

**Structure:** [Direction] + [Metric] + [Object] + [Context]

```
Examples:
- "Minimize the time it takes to reconcile monthly expenses"
- "Increase the confidence I have in my business decisions"
- "Reduce the likelihood of forgetting important tasks"
- "Increase the quality of meals I produce at home"
```

**Types of desired outcomes:**

| Type | Description |
|------|-------------|
| Speed | How quickly the job gets done |
| Stability | How consistently it gets done correctly |
| Efficiency | How little effort/resources are consumed |
| Output quality | How good the result of the job is |
| Throughput | How much can be accomplished per unit time |
| Variability reduction | How reliably outcomes are achieved |

## JOB MAPPING

Break a core job into its constituent steps:

```
CORE JOB: [Main job statement]

Step 1 — DEFINE: [What does the consumer do first?]
Step 2 — LOCATE: [What information/resources do they need?]
Step 3 — PREPARE: [What setup is required?]
Step 4 — CONFIRM: [How do they verify they're ready?]
Step 5 — EXECUTE: [The core action]
Step 6 — MONITOR: [How do they track progress?]
Step 7 — MODIFY: [How do they adjust when things go wrong?]
Step 8 — CONCLUDE: [How do they know they're done?]
Step 9 — EVALUATE: [How do they assess the result?]
```

**For each step, identify:**
- Desired outcomes (how they'd like to execute this step)
- Current frustrations (where current solutions fail)
- Opportunity magnitude (importance × current satisfaction gap)

## COMPETING SOLUTIONS ANALYSIS

Everything currently hired to do this job — not just direct competitors.

```
JOB: [Job statement]

Current solutions hired:
1. [Solution A] — hired when [context], abandoned when [limitation]
2. [Solution B] — hired when [context], abandoned when [limitation]
3. [Do it manually] — hired when [context], limitation: [friction]
4. [Do nothing] — hired when [context], consequence: [outcome]

Non-consumption (not doing the job at all):
  Who: [segment that doesn't attempt the job]
  Why: [barrier to entry — cost, complexity, awareness, access]
  Opportunity: [what it would take to unlock this segment]
```

## SWITCHING MOTIVATIONS

What causes consumers to fire one solution and hire another.

**The "Four Forces" of switching:**

```
PUSH (away from current solution):
  - Frustrations with current solution
  - Diminishing returns over time
  - Life circumstance changes

PULL (toward new solution):
  - New solution does the job better
  - New solution does additional jobs
  - Peer recommendation/social proof

ANXIETY (hesitation to switch):
  - Fear of data loss or disruption
  - Learning curve of new solution
  - Switching costs (financial, time)

HABIT (inertia of current solution):
  - "Good enough" threshold already met
  - Switching requires conscious decision
  - Existing integrations/dependencies
```

The new solution must generate enough PULL and address enough PUSH
to overcome ANXIETY and HABIT.

## JTBD INTERVIEW FRAMEWORK

When conducting consumer research, structure conversations around:

**TIMELINE RECONSTRUCTION:**
1. Tell me about the last time you [did this job].
2. Walk me through what happened from the beginning.
3. What were you doing just before you realized you needed to do this?
4. What did you try first? Then what?
5. At what point did you decide to [buy/switch to current solution]?

**ALTERNATIVE EXPLORATION:**
6. What else did you consider?
7. Have you tried other ways to do this? What happened?
8. Is there anything you used to use that you've stopped? Why?

**OUTCOME INVESTIGATION:**
9. What would "perfect" look like for this?
10. What still frustrates you about how you do this now?
11. What would make you switch to something else?

**DO NOT:**
- Describe your product and ask if they'd use it
- Ask "would you pay for X?" (behavior doesn't predict behavior)
- Lead with feature lists
- Ask hypothetical questions ("What if a product did X?")

**DO:**
- Ask about past behavior ("Tell me about the last time...")
- Let silences breathe
- Follow unexpected threads
- Ask "why" multiple times

## JOB PRIORITY MATRIX

| Job | Importance (1-10) | Current Satisfaction (1-10) | Job Gap | Priority |
|-----|-------------------|---------------------------|---------|---------|
| [Job 1] | | | | |
| [Job 2] | | | | |
| [Job 3] | | | | |

**Job Gap = Importance - Current Satisfaction**

```
Opportunity = Importance + (Importance - Current Satisfaction)
(Ulwick formula — double-weights importance)

If Opportunity > 15: Overserved — reduce complexity/cost
If Opportunity 10-15: Well-served — optimize, don't disrupt
If Opportunity < 10: Underserved — HIGH OPPORTUNITY
```
